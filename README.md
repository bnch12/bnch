# Banglachoti24 New Blog CMS

A self-hosted editorial CMS built with Next.js 16, vinext and Cloudflare Workers. The production target is `https://new.banglachoti24.com`.

## Runtime

- Next.js 16 / React 19
- vinext + Cloudflare Workers
- D1 for posts, categories, tags and comments
- R2 for image/media uploads

## Cloudflare production target

- Worker: `banglachoti24-new-blog`
- D1: `banglachoti24-new-blog`
- R2: `banglachoti24-new-blog-media`
- Custom domain: `new.banglachoti24.com`

The application uses the stable bindings `BLOG_DB` and `BLOG_MEDIA`. Resource IDs are generated by the provisioning script and are not hard-coded into application code.

### GitHub Actions deployment

The repository includes `.github/workflows/deploy.yml`. Add these repository secrets:

- `CLOUDFLARE_API_TOKEN`
- `CLOUDFLARE_ACCOUNT_ID`
- `ADMIN_PASSWORD`
- `ADMIN_SESSION_SECRET`

Every push to `main` will ensure the new D1/R2 resources exist, write the live D1 binding ID into the deployment config, apply pending D1 migrations, set the production admin secrets and deploy the Worker. The custom domain is declared in `wrangler.toml`.

### Local setup

Authenticate Wrangler with the Cloudflare account that owns `banglachoti24.com` and run:

`npm install`

`npx wrangler login`

`powershell -ExecutionPolicy Bypass -File .\scripts\setup-cloudflare.ps1`

The setup script provisions the D1/R2 resources, applies migrations, sets the admin secrets interactively and deploys the Worker.

## CMS

`/admin/` is the private publishing portal. It supports posts, drafts, publishing, categories, tags, media upload and comment moderation.

Published articles use the new site's canonical URL and sitemap base. Media is served from the Worker through the R2-backed `/media/*` route.

## WordPress migration

The existing migration tooling intentionally keeps `https://blog.suhanurrahman.com` as the legacy WordPress source. Imported content is written to the new D1 database and imported media is written to the new R2 bucket, with article media URLs rewritten to `https://new.banglachoti24.com/media/...`.

The migration workflow is manually dispatchable and can be triggered with the existing `MIGRATE-WORDPRESS-ONCE` guard. It uses the new D1/R2 resource names defined above.
